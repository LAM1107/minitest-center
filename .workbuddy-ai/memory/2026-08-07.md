# 2026-08-07

## 框架优化审查 (minitest-center)
对 Minitest 小程序自动化测试框架做了代码 + schema 通读，给出优化清单。

### 关键发现
- **功能性 bug**：`BasePage.hook_network_monitor()`（base_page.py:173）定义了但全仓库无调用点。DB 步骤模式下 `BasePage.check_api_error` 读 `globalData.__api_error__` 永远为 null，`normal` 模式的接口 500 检查实际不生效；`ActionExecutor._check_api_error_for_assertion` 的 Minium Network Log 路径也没被 StepExecutor 接通。需在用例 setup 调 `ui.hook_network_monitor()` 并补验证用例。
- **性能**：`find_public_action_id`（mysql_case_repository.py:1285）全表扫描后在 Python 过滤，应改 SQL；`list_test_cases` 对每个 case 单独查 steps（N+1），而公共动作已用批量模式，应统一。
- **可靠性**：`claim_next_job` 用 `FOR UPDATE` 只防并发领取，agent 崩溃后 run_records 永远 `running`，缺卡死任务超时回收；心跳无离线判定。
- **可维护性**：center 与 release 各有一份 `mysql_case_repository.py` 拷贝易漂移；输入解析两套（`_split_csv_inputs` vs `ActionExecutor._parse_inputs`）；force_click / 断言里残留 DEBUG 打印与函数内 import。
- **其他**：报告 HTML 全文回写 DB（MEDIUMTEXT）撑大存储；缺 pytest 单测；中心 API 服务代码不在本仓库内。
